## 3. **새로 발견한 비판점**

### 3.1 화면에 뜨는 시대와 크레딧에 적히는 시대가 다르다 — ✅ **해결됨 (07-26)**

> **조치:** `EraNames` 의 한국어 이름을 화면 자막에 맞췄다
> (`선사시대`→`석기시대`, `고대 그리스`→`청동기 시대`, `중세`→`중세 시대`, …).
> 열거형 멤버도 `Era.Greek` → `Era.BronzeAge` 로 개명했다(정수 직렬화라 씬 데이터는 그대로).
> `eraYearText` 를 비워두면 이제 같은 이름으로 자동 폴백된다(`GameEntry.EraLabel`).
> **부수 효과: 고증이 실제로 맞아졌다** — 상형 문자(기원전 3200년)와 청동기(기원전 3300년)가
> "청동기 시대" 안에 들어가는 건 옳다. 3.1이 지적한 "이집트 상형문자 = 고대 그리스" 문제가 사라진다.
> **남은 것:** 부력의 발견(아르키메데스, 기원전 3세기)이 청동기 칸에 있는 것과,
> 증기 기관이 `era: 3`(중세 시대)인 것. 둘 다 라벨이 아니라 **배치** 문제라 인스펙터에서 옮겨야 한다.

아래는 조치 전 기록이다.

`eraYearText` 는 시대 라벨을 손봤지만, **LLM 프롬프트와 크레딧이 쓰는 이름은 `Era` enum 이다.**

```csharp
// EndingTypes.cs:39
{ Era.Greek, "고대 그리스" },
```

`ToOutcome()` 은 `era.ToKorean()` 을 쓰고([GameFlowController.cs:66](../Assets/01_Scripts/Core/GameFlowController.cs:66)),
`FallbackEndingNarrator` 는 그 값을 `— {o.era} —` 로 그대로 찍는다.

> 플레이어가 본 것: **청동기 시대**
> 크레딧에 뜨는 것: **— 고대 그리스 —**
> Gemini가 받는 것: `- 시대: 고대 그리스 / 사건: 상형 문자의 발명`

**라벨 수정이 표시 계층에만 적용되고 데이터 계층은 그대로다.** 고증 지적이 사라진 게 아니라
"이집트 상형문자 = 고대 그리스"가 엔딩 텍스트로 이동했을 뿐이다. 게다가 **아르키메데스(기원전 3세기)를
청동기 시대 칸에 넣어서**, 유일하게 그리스가 맞았던 항목까지 화면상 틀리게 됐다.

**증기 기관이 `era: 3`(중세)인 건 그대로다.** 화면에도 `중세 시대` 로 뜬다. 가장 눈에 띄는 고증 오류.

### 3.2 네트워크가 끊기면 이 게임의 주제 장치가 통째로 사라진다 — 최우선

```csharp
// EndingCreditController.cs:155
if (namePrompt == null || !saveToGallery || endingImage == null)
    yield break;          // ← 이름 입력 자체를 건너뛴다

// EndingCreditController.cs:343
if (endingImage == null) { …return; }   // ← 갤러리 저장도 건너뛴다
```

이미지 생성 실패 = **이름 붙이기 없음 + 갤러리 저장 없음**. 텍스트는 `FallbackEndingNarrator` 라는
완전한 폴백이 있는데, **이미지에는 폴백이 하나도 없다.**

07-25 문서 §5.3 은 "플레이어가 자기 세계에 이름을 붙인다 — 주제와 가장 정확히 맞물리는 장치"를
**첫 번째 방어 카드**로 꼽았다. 그 카드가 행사장 와이파이 한 줄에 매달려 있다.
Pollinations는 무료·무인증이라 레이트리밋과 지연이 흔하고, 타임아웃은 60초로 잡혀 있다.

> 폴백 이미지(단색 + 시대 텍스트라도) 하나만 만들면 이 의존이 끊긴다. 코드 3~4줄.

### 3.3 엔딩 진입 시 최대 20초 검은 화면 — 연출 공백

```csharp
yield return new WaitForSeconds(leadInDuration);   // 3초
yield return narration;                            // Gemini 최대 20초
```

`PrepareInitialState()` 가 크레딧 텍스트를 비우고 배경 alpha를 0으로 만들어 두므로,
대본이 늦으면 **아무 표시도 없는 검은 화면**이 최대 23초간 유지된다.
`99_Ending.unity` 에 로딩 표시 오브젝트는 없다(확인함). 심사 시연 중이면 "멈춘 줄 알았다"가 나온다.

### 3.4 빅뱅 실패 = 앱 강제 종료 — 기획서와 정면 배치

```csharp
// BigBangSceneFlow.cs:61-67
if (failUI != null) failUI.SetActive(true);
if (quitDelay > 0f) StartCoroutine(QuitAfterDelay());   // 1.5초 뒤 Application.Quit()
```

기획서 6.1: *"빅뱅 미니게임 실패 → 게임 오버되고 **다시 빅뱅부터 시작함**"*.
실제로는 **1.5초 뒤 게임이 꺼진다.** 게임의 **첫 30초**에서 실패한 심사위원은
게임을 다시 실행해야 한다. 잼 심사에서 이보다 나쁜 실패 모드는 없다.

곁들여, 같은 파일의 `mainSceneName`(인스펙터 값 `00000_Player`)은 **읽히지 않는 죽은 필드**다 —
코드는 `SceneManager.LoadScene("00000_Title")` 로 하드코딩돼 있다([BigBangSceneFlow.cs:57](../Assets/01_Scripts/Mini_BigBang/BigBangSceneFlow.cs:57)).
인스펙터를 고쳐도 목적지가 안 바뀐다.

### 3.5 선사에서 끊긴 다음 판은 BGM이 타이틀 곡으로 돈다 — 재현 가능한 버그

`EraBgmDirector` 는 타이틀 씬의 `'AudioManager '` 오브젝트에 함께 붙어 있고,
`AudioManager.dontDestroyOnLoad: 1` 덕분에 **씬을 넘어 살아남는다**(여기까지는 정상 동작).
문제는 상태가 같이 살아남는다는 것이다.

```csharp
// EraBgmDirector.cs
bool sameEra = hasPlayed && currentEra == era;
if (sameEra) return;      // ← 곡을 다시 걸지 않는다
```

반면 타이틀로 돌아오면 `AudioManager` 중복 인스턴스가 `startupBgm`(타이틀 곡)을 **뒤에서 갈아끼운다**.
디렉터는 그 사실을 모른다.

> **재현:** 1판에서 불 피우기(선사) 실패 → 엔딩 → 갤러리 → 타이틀(타이틀 곡 재생)
> → NEW WORLD → 2판 선사시대: `currentEra == Prehistoric` 이라 `sameEra` → **타이틀 곡이 그대로 흐른다.**

하필 07-25 문서 §7이 권장한 시연 순서("**일부러 불 피우기를 실패**한 뒤 다시 플레이")가
정확히 이 경로다. `StartFlow()` 에서 `EraBgmDirector.Instance?.Stop()` 한 줄이면 끝난다.

### 3.6 부수적으로: 엔딩·갤러리·타이틀 전용 BGM이 없다

`SceneBgm` 컴포넌트는 **어느 씬에도 배치돼 있지 않다**(전 씬 검색 확인). `EraBgmDirector.Stop()` 을
부르는 곳도 없다. 따라서 **마지막에 플레이한 시대의 BGM이 엔딩 크레딧과 갤러리까지 그대로 흐른다.**
핵전쟁으로 끝난 판이든 미래까지 완주한 판이든 같은 곡이다 — 엔딩 톤이 판마다 달라야 하는 게임에서
음악만 그걸 따라가지 않는다.

### 3.8 전환 연출이 게임 시간의 70%다

인스펙터 값에서 계산한 게임당 고정 오버헤드:

```
페이드아웃 0.3 + 보더 축소 0.35 + 대기 0.6 + 보더 확대 0.35 + 인트로 1.25 = 2.85초
시대 전환 게임(6개)은 + 보더 스프라이트 페이드 0.3 + 연도 연출 1.5 = +1.8초
```

- 실제 게임 시간 합계: **93.5초** (프리팹 `timeLimit` 합)
- 전환 시간 합계: 19 × 2.85 + 6 × 1.8 = **약 65초**

**전체 158초 중 41%가 전환이다.** "만져라! 메이드인 와리오"의 게임 간 간격은 1초 남짓이다.
19개 프리팹 전부 `gameDescription` 이 채워져 있어 인트로(1.25초)는 **매번** 뜬다.
장르 정체성이 흐려지는 지점이고, 07-25 문서 §1.3("장르가 주제를 방해한다")의 반대편 문제다.

### 3.9 제한시간이 3초에서 10초까지 흩어져 있고, 성공하면 남는 시간을 버린다

`timeLimit`: 3 / 3 / 3 / 3 / 3 / 3.5 / 4 / 4 / 5 / 5 / 5 / 5 / 5 / 5 / 8 / 8 / 8 / **10**

`TimedMiniGame` 은 의도적으로 이렇게 설계돼 있다:

```csharp
// TimedMiniGame.cs:70-74 — 성공은 제한시간이 다 차야 통지된다
if (successPending) { if (elapsed >= timeLimit) ReportFinished(true); return; }
```

와리오웨어 규칙으로는 옳다(성공/실패 간격이 일정해야 리듬이 산다). 문제는 **길이**다.
`UfoCowGame`(8초)·`GalTrashGame` 등 `SucceedWhenTimeUp` 을 쓰는 게임에서 1초 만에 클리어하면
**남은 7초를 아무 할 일 없이 본다.** 3초 게임에서는 무해한 규칙이 8~10초 게임에서는 데드타임이 된다.

### 3.10 기획서 2.3 "플레이 제한시간 시스템"이 통째로 미구현

전역 러닝 타이머는 코드 어디에도 없다. `MiniGameTimerPresenter` 는 **미니게임 개별 타이머**만 그린다.
기획서의 "선사 시대 입장 순간부터 카운트" 와 6.1의 "제한시간 종료" 행은 대응 코드가 없다.
기획서에 "추가 작성 필요 (아직 미정)"으로 남아 있으니 **기획서에서 지우는 게 맞다** — 심사용 문서에
미구현 시스템이 남아 있으면 그 자체가 지적거리다.

### 3.11 데이터 계층의 새 문제

- **`eventLabel` 빈칸이 6개로 늘었다** (`RubGame` · `ArchimedesBath` · `CarryGame ` · `PenicillinFindGame` · `StockGame` · `GalTrashGame`).
  폴백은 프리팹 이름이므로 Gemini는 이렇게 받는다:
  `- 시대: 근대 / 사건: CarryGame  / 결과: 성공` — **끝에 공백까지 붙은 채로.**
- **`PenicillinFindGame` 은 `successVisual`·`failureVisual` 이 둘 다 비어 있다.** 성패와 무관하게
  엔딩 이미지에 아무것도 기여하지 않는 유일한 변화 게임이다. `ArchimedesBath` 는 `failureVisual` 이 비었다.
- **핵전쟁 `visualWeight` 가 7 → 10(최대)으로 올랐다.** 시스템 프롬프트는 weight가 높은 요소를
  "전경의 주요 피사체"로 배치하라고 지시한다. 즉 **핵전쟁 실패 판은 버섯구름이 화면 주인공이 되도록
  명시적으로 요구**하고 있다. 07-25 문서 §4.3의 위험이 커졌다. 시연 전 실물 확인이 필수다.
- **폴백 크레딧이 문장 조각으로 깨진다.** 고인돌의 `successMeaning` 은
  `"너의 세계는 고인돌 유적지가 관광자원으로 활발히 사용되고 있으며"` — LLM이 이어 쓰라고 만든 조각인데,
  `FallbackEndingNarrator` 는 이걸 **한 줄로 그대로 출력**한다. 네트워크가 없으면(3.2) 보게 되는 게 이 화면이다.
  게다가 이 항목만 2인칭("너의 세계는")이라 다른 줄과 어투가 어긋난다.

### 3.12 소소하지만 사고 나기 쉬운 것

- **`CarryGame` 프리팹이 둘이다.** `CarryGame.prefab`(30KB, 07-25)과 `CarryGame .prefab`(**끝에 공백**, 22KB, 07-26).
  흐름에 등록된 건 **공백 있는 쪽**이다. 파일명 끝 공백은 일부 빌드/압축 툴에서 깨지고,
  위에서 본 대로 LLM 프롬프트에도 그대로 실린다. 안 쓰는 쪽과 함께 정리해야 한다.
- **`MarkEarlyEnding` 만 `eventLabel` 폴백을 안 탄다.**
  `RunResult.Record` 는 `prefab.name` 폴백을 쓰지만
  ([GameFlowController.cs:65](../Assets/01_Scripts/Core/GameFlowController.cs:65)),
  바로 다음 줄의 `MarkEarlyEnding(…, entry.eventLabel, …)` 은 원본을 넘긴다.
  핵심 6개는 지금 전부 라벨이 채워져 있어 무해하지만, 하나만 비면
  `"인류는 선사시대에서 ''에 실패해"` 가 프롬프트로 나간다.
- **갤러리가 모든 이미지를 한 번에 메모리에 올린다.** 1280×720 RGBA ≈ 3.5MB × 엔트리 수.
  시연용으로 미리 채워두는 정도(3~5장)면 문제없지만, 잼 기간 내내 테스트한 PC로 시연하면 수십 장이 쌓인다.
- **문서가 낡았다.** `CLAUDE.md` 와 `docs/기획.md` 는 "총 18개(일반 3 / 변화 9 / 핵심 6)"라고 적고 있다.
  실제는 19개(일반 4). 심사위원에게 기획서를 준다면 이건 즉시 들킨다.

## 4. 안전 확인 (문제 없음)

의심해서 확인했고 **괜찮았던** 것들이다. 다시 파헤칠 필요 없다.

- **API 키는 저장소에 없다.** `.gitignore:113-114` 가 `gemini_api_key.txt` 와 `.meta` 를 모두 제외하고 있고,
  `git ls-files` 에도 없다. 다만 빌드에 동봉되면 추출 가능하다 — `GeminiApiConfig` 주석대로 **제출 후 키 폐기**할 것.
- **Build Settings에 5개 씬 전부 등록돼 있다** (`00_BigBang` / `00000_Title` / `00000_Player` / `99_Ending` / `00000_Gallery`).
  씬 전환으로 죽는 경로는 없다.
- **`preloadOnAwake: 0` 이 제대로 꺼져 있다.** `GameFlowController.InjectGamePrefabs()` 의 경고 조건에 걸리지 않는다.
- **미니게임 프리팹에 카메라·EventSystem이 없다.** 계약 5번 위반 없음(전 프리팹 검사).
- **레거시 `Input` 사용이 0건이다.** 전부 `UnityEngine.InputSystem`.
- **`RatCatchMiniGame`(가장 최근 추가)은 계약을 정확히 지킨다.** `Awake` 는 캐시만, `OnTimedPlay/StopAndReset` 분리,
  `StopAllCoroutines` 로 멱등 보장.
- **`fastForwardMultiplier` / `useImageCache` 가 `99_Ending.unity` YAML에 없는 건 정상이다.**
  Unity는 직렬화 데이터에 없는 필드에 C# 필드 초기값(5f / false)을 그대로 남긴다. 버그 아님.
